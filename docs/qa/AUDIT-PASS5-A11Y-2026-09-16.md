# Pass 5 — Accessibility & keyboard/screen-reader experience — 2026-09-16

Automated axe-core 4.10.2 audits on every template (home, collection,
list-collections implied by nav, product, cart, search results,
contact, blog, article, 404, password) plus every open-dialog state
(quick view, cart drawer, predictive search), and manual keyboard,
focus, contrast, and reduced-motion testing on the live dev theme.

## Issues found and fixed

1. **Utility bar content sat outside any landmark** (axe `region`,
   every page) — the announcement message and country/language
   selectors were in a bare div. Now `role="region"` with a
   translated label (`general.utility_bar_label`, "Store
   preferences", ×5 locales).
2. **Password layout had no `<main>` landmark** (axe
   `landmark-one-main` + `region`) — content_for_layout now renders
   inside `<main id="qc-main">`. Page re-audits clean.
3. **Blank page titles rendered "– ShopName"** (password page): the
   title now falls back to the shop name, and the dedupe check uses
   the resolved value.
4. **Slideshow arrows always smooth-scrolled** — `go()` now uses
   instant scrolling under prefers-reduced-motion, matching the
   existing back-to-top behavior (autoplay was already fully guarded).

## Verified (no defects)

- **axe: zero theme violations on every template and every open
  dialog.** The only remaining report is Shopify's own preview-bar
  iframe (`#PBarNextFrame`, absent on live stores).
- **Keyboard**: skip link is the first tabbable and visible on focus;
  logical tab order; 2px offset focus ring on keyboard focus
  (`:focus-visible`, verified via real key events); variant radios
  operate with arrow keys and drive full page sync; modal dialogs
  trap Tab (native showModal) and return focus to their trigger
  (quick view, drawer, lightbox); search dialog focuses its input on
  open; mobile menu closes on Escape with focus back on the summary.
- **Escape on native dialogs**: an injected synthetic Escape reaches
  the document unprevented and uncaptured (instrumented: keydown
  received, `defaultPrevented` false, no cancel fired) but cannot
  trigger Chrome's native close-request path — a limitation of
  synthesized input, not theme code. Nothing in the theme listens for
  or prevents Escape on these dialogs, so real user Escape closes
  them via untouched browser behavior; the age gate's cancel
  prevention is scoped to the gate element only.
- **Contrast**: all sampled pairs ≥ 10:1 (body, muted, stock, badge,
  breadcrumb, nav, primary button); derived `--qc-ink-soft` keeps
  ≥ 4.5:1 by construction (76% mix).
- **Semantics**: one h1 per page with logical h2/h3 flow; `role=list`
  wherever list styling is stripped; `aria-current` on nav and
  pagination; product image alt from product data; decorative and
  duplicate-link imagery hidden (`aria-hidden` + `tabindex=-1` on
  card media links); toast aria-hidden with the live region carrying
  the announcement; closed dialogs are display:none (silent to AT);
  errors `role=alert` and mirrored to `qc:announce`; comment and
  customer forms fully labeled with autocomplete.
- **Reduced motion**: durations zeroed via CSS tokens, slideshow
  autoplay never starts, back-to-top and slideshow scrolls instant.

Gates: theme check 94 files / 0 offenses, node --check, locale parity
255 × 5, provenance clean.
